================================================================================
          ARQUITECTURA DE AUTOZEN: FRONTEND (FLUTTER) + BACKEND (.NET)
================================================================================

1. DIVISION DE RESPONSABILIDADES
--------------------------------------------------------------------------------
El sistema esta desacoplado profesionalmente en dos capas independientes:

  A) FRONTEND (Flutter / Dart):
     - Corre en clientes: Android, Windows Desktop, iOS, Web.
     - Responsabilidad UNICA: Interfaz de usuario (pantallas, botones, formularios,
       tarjetas, tablas) y consumir la API REST del backend.
     - NO tiene conexion a base de datos.
     - NO tiene logica de servidor.

  B) BACKEND (.NET 10 / C# / Dapper):
     - Corre en servidor: Carpeta ackend/.
     - Responsabilidad UNICA: Conectarse a PostgreSQL, ejecutar queries SQL rapidos
       mediante Dapper, validar reglas de negocio, procesar DTOs y exponer endpoints
       REST seguros (JSON).

3. LO QUE SE ELIMINO Y POR QUE
================================================================================

1. lib/dtos/ (ELIMINADO):
   - Los DTOs de creacion y recepcion de base de datos pertenecen al backend.
   - En .NET ya estan todos en ackend/DTOs/ (ej. CreateCamionDto.cs).
   - Mantenerlos en Flutter duplicaba codigo y generaba confusion. En Flutter
     solo se necesitan los lib/models/ para recibir y pintar el JSON.

2. lib/pages/ (ELIMINADO):
   - Era un duplicado innecesario de lib/views/. Todas las pantallas van en iews/.

3. ESTRUCTURA_MVC.txt (ACTUALIZADO A ESTE ARCHIVO):
   - El archivo anterior asumia que todo el sistema viviria dentro de Dart.
